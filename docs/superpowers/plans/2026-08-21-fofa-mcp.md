# FOFA MCP Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add five Scope-aware FOFA MCP tools to LuaN1aoAgent Executors while keeping credentials host-side, bounding model output, persisting complete results as Artifacts, and enforcing durable per-Task quotas.

**Architecture:** A per-Run host-side stdio MCP child owns FOFA HTTP calls and request/result policy. A Runtime-owned MCP client injects trusted Task and Scope context, persists quotas/cursors, and a Pi bridge exposes sanitized TypeBox tools only to Executor sessions. Complete MCP results stay on the host and are converted into Task Artifacts before a bounded summary reaches the model.

**Tech Stack:** Node.js 25+, TypeScript/NodeNext, `@modelcontextprotocol/server` v2, `@modelcontextprotocol/client` v2, Zod 4, TypeBox/Pi tools, `node:sqlite`, `node:test`.

**Design reference:** `docs/superpowers/specs/2026-08-21-fofa-mcp-design.md`

`start()` uses `process.execPath` and `fileURLToPath(new URL("./fofa-server.js", import.meta.url))`, the minimal child environment, and piped stderr. Verify the exact five tools from `listTools()`.

For a call: validate model args/cursor; calculate reservation; reserve through `RuntimeStore`; inject `_runtime`; call MCP with linked cancellation; require exactly one JSON text block; store `nextProviderToken` only in a host map; return `cursor:${randomUUID()}`; release quota only for definitely pre-dispatch failures; append sanitized metrics.
